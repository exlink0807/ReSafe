# 비가시 워터마크 (압축·리사이즈에 강한 방식)

화면: 예방 → 비가시 워터마크 / 유출 이미지 워터마크 확인. 코드: `lib/security/robustWatermark.ts`

## 무엇이 바뀌었나

| | 기존 (`lib/security/watermark.ts`, LSB) | 현재 (`robustWatermark.ts`, DCT-QIM) |
|---|---|---|
| 기록 위치 | 픽셀 최하위 비트 | 256×256 기준 해상도의 8×8 DCT 중저주파 계수 |
| JPEG 압축·카톡 전송 | 사라짐 | 남음 |
| 리사이즈 | 사라짐 | 남음 (기준 해상도 256px 이상일 때) |
| 검증 기능 | 없음 | 있음 (내 기록에서만 조회) |
| 받는 사람별 사본 | 없음 | 있음 (사람마다 다른 번호 → 유출 경로 좁히기) |

## 동작

1. 밝기 채널을 256×256로 줄이고, 블록마다 DCT 계수 5개에 QIM으로 비트를 넣는다.
2. 96비트(식별자 8 + 코드 80 + CRC 8)를 고정 시드로 흩어 비트당 약 133번 반복해 넣는다.
3. 바뀐 양만 쌍선형 보간으로 원래 크기로 키워 원본에 더한다 (3회 반복으로 반올림 손실 보정).
4. 검출은 같은 256×256로 줄여 계수를 읽고 다수결로 비트를 정한 뒤, 식별자와 CRC가 맞을 때만 코드로 인정한다.
5. 처리는 전부 브라우저 안에서 한다. 사진은 서버로 보내지 않고, 코드와 메모(곳·목적·받는 사람)만 로그인 시 서버에 저장한다 (RLS로 본인만 조회).

## 측정 결과 (scikit-image 예제 사진 5장, 1600px 원본)

- 화질 손상: PSNR 약 40dB (눈으로 구분하기 어려운 수준)
- 카톡식(1280px·품질 75), 인스타식(1080px·품질 80), 절반 축소+품질 60, 4분의 1 축소+품질 70, 품질 70 재압축 2회: **25/25 검출 성공**
- 원본 크기(400~741px)에서 JPEG 품질 90·70·50, 75% 축소, 150% 확대, 밝기 변경: 모두 성공
- 워터마크 없는 사진에서 잘못 검출: 0건
- 실패: 5% 크롭(전부 실패), 기준 해상도(256px)보다 작게 줄인 경우

## 한계 (발표·보고서에 꼭 적을 것)

- 크롭·회전·좌우 반전·화면 캡처 후 편집에는 약하다.
- 딥페이크 생성 과정(얼굴만 떼어 다른 사진에 합성)을 거치면 워터마크는 대부분 사라진다. 워터마크는 "원본 사진이 어디서 새어 나갔는지"를 좁히는 도구지, 합성을 막는 도구가 아니다.
- 사본이 다시 전달됐을 수 있으므로 검출 결과만으로 특정인을 단정하지 않는다.
- 알고리즘이 공개되어 있으면 같은 방법으로 덮어쓰거나 지울 수 있다. 운영 시에는 시드를 비공개 키로 바꿔야 한다.
