## 2. AI 레드팀 자가 점검 결과

| 지표 | v1 (점검 전) | v2 (현재) |
|---|---|---|
| 공격 탐지 (15종) | 6/15 | **15/15** |
| 정상 상담 오탐 (17종) | 5/17 | **0/17** |
| 위기 신호 감지 (3종) | 1/3 | **3/3** |
| 출력 가드 (6종: 프롬프트 유출, 남의 전화·이메일, 2차 가해, 본인 번호 허용, 정상 응답) | - | **6/6** |

브라우저 시연 확인
- 가드 ON: 사칭 공격 차단, 메시지 앞에 넣은 `<img onerror>`는 글자로만 표시
- 가드 OFF + 토큰 없음: 서버가 가드를 켠 채로 처리 (차단)
- 가드 OFF + 데모 토큰: 유출 시연 메시지 (가상 데이터)
- 정상 문장 "가해자가 제 부탁을 무시하고…": 정상 응답

주의: v2는 이 문장 세트를 보면서 고쳤으므로 이 세트에서는 점수가 높게 나온다. 팀원이 따로 만든 **처음 보는 공격·정상 문장**으로 다시 재야 일반화 성능을 말할 수 있다.

## 3. 남은 과제

- 실제 LLM(ANTHROPIC_API_KEY)을 연결한 상태에서 출력 가드 실측 (지금 출력 가드 점검은 위험한 응답을 가정한 시험)
- 규칙 다음 단계로 LLM 기반 2차 판정 추가
- CSP를 nonce 방식으로 바꿔 `'unsafe-inline'` 제거
- RLS 교차 접근 테스트 자동화 (사용자 A 토큰으로 B 데이터 조회 → 0행)
- 클라이언트 폴백(`client_fallback`)은 서버 연결 실패 시에만 쓰는 시연용 응답이다. 운영에서는 폴백 대신 오류를 보여주는 게 맞다
