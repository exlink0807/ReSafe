# 화이트햇 엔진 · 공개 웹 재유포 탐색

피해자가 가진 사진·영상(받은 합성물 사본, 원본 사진)으로 공개 웹에 퍼진 복사본을 찾고, 지각 해시로 유사도를 계산한다.
화면: 추적·삭제요청 → 맨 위 카드.

## 흐름

1. 피해자가 사진 또는 영상을 고른다. 영상은 브라우저에서 장면 4장을 뽑고, 영상 파일 자체는 보내지 않는다.
2. 브라우저가 최대 1024px JPEG로 다시 그린다 (EXIF·위치 정보 제거).
3. 피해자가 전송에 동의해야 검색한다. 서버도 `consent: true`가 없으면 거부한다.
4. 서버(`/api/trace/search`)가 로그인 확인 → 사용자별 횟수 제한(10분 6회) → 이미지 재인코딩 → 검색.
5. 검색 공급자
   - `GOOGLE_VISION_API_KEY`가 있으면 Google Cloud Vision Web Detection으로 공개 웹에서 완전 일치·부분 일치·유사 이미지와 그 이미지가 실린 페이지를 찾는다.
   - 키가 없으면 DEMO: 업로드한 이미지를 압축·크롭·밝기 변경·흐림·좌우 반전한 가상 재유포본과 무관한 이미지를 만들어 비교한다. 검색은 가상이지만 유사도 계산은 실제다.
6. 후보 이미지를 SSRF 방어를 거쳐 받아 aHash·dHash 유사도를 계산하고 바로 버린다. 받지 못한 후보는 검색엔진 판정 기준 추정치로 표시한다.
7. 결과는 추적 결과 표에 추가된다. 피해자가 "피해 확인"을 눌러야 삭제요청을 만들 수 있다.

## 지키는 선

- 본인 콘텐츠만 검색한다. 다른 사람을 찾는 용도가 아니다.
- 공식 검색 API만 쓴다. 검색엔진 화면 긁기, 비공개 계정·채널 접근, 로그인 우회, 사이트 공격은 하지 않는다.
- 서버에 기준 이미지·후보 이미지·URL을 저장하지 않는다. 감사 로그에는 "검색했다"와 건수만 남긴다.
- 후보 이미지 수집은 SSRF 방어(`lib/security/ssrf.ts`): http/https, 80/443 포트만, 사설·루프백·링크로컬·메타데이터 IP 차단, 리다이렉트마다 재검사, 6초·5MB 제한, 이미지 형식만.
- 결과 화면은 썸네일을 자동으로 띄우지 않는다. 링크를 열 때 피해 콘텐츠가 보일 수 있다고 안내한다.

## 유사도 해석

| 변형 | DEMO 측정 예 |
|---|---|
| 리사이즈 + 강한 JPEG 압축 | 98% |
| 밝기·채도 변경 | 94% |
| 가장자리 10% 크롭 | 70% |
| 좌우 반전 | 54% (지각 해시의 약점) |
| 무관한 이미지 | 45% |

유사도는 "같은 이미지의 변형일 가능성"이지 "동일 인물일 확률"이 아니다.

## 한계

- 역이미지 검색은 이미 알고 있는 이미지의 복사·편집본을 찾는다. 얼굴만 바꿔 다른 사진에 합성한 경우(원본 배경이 전혀 다른 경우)는 찾기 어렵다. 얼굴 인식 기반 검색은 다른 사람 추적에 악용될 수 있어 넣지 않았다.
- 검색 엔진에 색인된 공개 페이지만 찾는다. 비공개 메신저·단톡방은 대상이 아니다.
- 기준 이미지를 Google로 보내야 검색할 수 있다. 그래서 명시적 동의를 받는다. 장기적으로는 플랫폼과의 해시 공유(StopNCII 방식)처럼 원본을 보내지 않는 방식이 바람직하다.
- 후보 이미지를 서버가 일시적으로 받아 해시를 계산한다. 운영 전 법률 검토가 필요하다.
- DNS rebinding은 완전히 막지 못한다. 운영 환경에서는 외부 요청 전용 프록시를 권장한다.

## 설정

`.env.local`
```
GOOGLE_VISION_API_KEY=   # 비우면 DEMO 모드
```
Google Cloud 콘솔 → Cloud Vision API 사용 설정 → API 키 생성 → 키 제한을 "Cloud Vision API"로 설정. 결제 계정 연결이 필요하며, 무료 사용량과 요금은 콘솔에서 확인한다.
