RE:SAFE 기능명세서
해커톤 데모 기준 · 2026.11.20 · 팀 공유용
1. 한 줄 소개
RE:SAFE는 딥페이크, 불법 촬영물, 비동의 유포, 온라인 협박 피해자가 신고 → 콘텐츠 탐색 → 증거 보존 → 삭제 요청 → 재유포 감시 → 회복 → 예방까지 한 곳에서 지원받는 AI 플랫폼이다.
2. 왜 만드나 (문제 정의)
• 피해자가 경찰, 플랫폼, 상담기관마다 같은 일을 처음부터 다시 설명해야 한다.
• 피해 콘텐츠가 어디에 퍼졌는지 혼자 찾아야 하고, 찾는 과정 자체가 2차 피해가 된다.
• 삭제해도 다시 올라오는데 지켜볼 방법이 없다.
• 신고 이후 심리 회복과 재발 예방까지 이어 주는 곳이 없다.
3. 설계 원칙
1.  한 번만 말한다. 한 번 접수한 내용은 모든 단계가 공유한다.
2.  결정은 본인이 한다. AI는 정리하고 제안하며, 확인·삭제·공유는 피해자가 직접 선택한다.
3.  최소 수집. 원본 얼굴 이미지는 서버에 보내지 않고 해시·임베딩 같은 지문만 쓴다.
4.  과장하지 않는다. 영구 삭제를 보장하지 않고, 유사도는 동일인 확률이 아니며, 시뮬레이션은 DEMO로 표시한다.
5.  허가된 범위에서만. 비공개 접근, 인증 우회, 무단 침입은 구현하지 않는다.

5. 단계별 상세
5.1 Dashboard
• 왜: 피해 대응은 여러 갈래라 전체 진행 상황이 보이지 않으면 막막하다.
• 취지: 한 화면에서 현황과 다음 할 일을 파악하게 한다.
• 기능: 접수 사례, 탐색 후보, 증거, 삭제 요청, 모니터링, 회복 세션 카드 / 대응 타임라인 / 전체 진행률(우측 패널) / 통합 보고서 인쇄·PDF 저장
• 데모: 다른 메뉴에서 한 작업이 자동 반영된다.
5.2 Report (AI 피해 신고·상담)
• 왜: 긴 신고 양식은 그 자체로 부담이고, 사람 앞에서 말하기 어려운 피해가 많다.
• 취지: 사람보다 AI에게 말할 때 수치심이 낮다. 한 번 말하면 AI가 기록하고 정리한다.
• 기능:
    ◦ 질문을 한 번에 하나씩 대화로 진행하고, 이미 답한 내용은 다시 묻지 않는다.
    ◦ 모든 질문에 「모름 / 기억나지 않음 / 확인 필요 / 답변하고 싶지 않음」 선택지를 둬서 강요받는 느낌을 없앤다.
    ◦ 답변을 구조화해 수정할 수 있게 하고 진술서 초안(.txt)을 만든다.
• 주의: 경찰 신고가 자동 접수되는 것이 아니며, 정식 조사에서 추가 진술이 필요할 수 있다고 안내한다.
• 데모: 질문 6개(피해 유형, 인지 시점, 플랫폼, 가해자, 협박, 희망 지원)로 단순화되어 있다. 실제 AI 모델 연결은 아직 없다.
• 보완 예정: 위기 신호 감지 시 상담 연결, 미성년자 분기, 대화에서 신고서 필드 자동 매핑
5.3 Trace & Remove (탐색 · 삭제 · 재유포 감시)
핵심 기술 영역이며 하위 모듈로 나뉜다.
A. AI Content Search (후보 탐색)
• 왜: 피해자가 직접 찾는 것은 고통스럽고 범위에도 한계가 있다.
• 기능: 후보 목록(플랫폼, URL, 발견 시각, AI 유사도) 표시, 피해자가 「피해 확인 / 무관 / 추가 확인」으로 직접 판정
• 주의: 유사도는 동일인일 확률이 아니다. 오탐 가능성이 있어 반드시 본인이 확인한다.
• 데모: 가상 후보 5건(DEMO). 실제 외부 검색은 하지 않는다.
B. 증거 등록 → 삭제 요청
• 왜: 삭제 요청에는 근거가 필요하고, 증거는 삭제되기 전에 보존해야 한다.
• 기능: 확인한 후보를 증거로 등록(SHA-256) → 플랫폼별 삭제 요청 생성 → 상태 관리(요청 준비, 요청 완료, 검토 중, 삭제 확인, 반려, 확인 불가)
• 주의: 플랫폼의 캐시와 백업은 직접 지울 수 없고, 영구 삭제도 보장하지 않는다.
C. Re-leak Monitoring (재유포 감시)
• 왜: 지워도 다시 올라오는 것이 피해가 끝나지 않는 가장 큰 이유다.
• 기능: 기준 이미지의 지각 해시를 저장하고, 새 이미지와 해밍 거리로 비교해 재유포 후보를 알린다.
• 데모: 업로드한 이미지로 실제 계산한다(크롭, 압축, 밝기 변경 정도의 변형 탐지). 플랫폼 업로드 단계 차단은 해당 플랫폼과의 협력이 필요해 범위 밖이다.
D. 자체 화이트햇 엔진 (OSINT, 보안 분석, Threat Hunting, 포렌식)
• 취지: 외부 전문가에게 전부 맡기지 않고 팀이 공개 정보 분석 역량을 쌓는다.
• 범위: 공개 정보, 자체 테스트 환경, 명시적으로 허가된 시스템만 대상으로 한다.
• 데모: Threat Hunting 결과는 시뮬레이션(SIMULATED)이며, 사실 / 추정을 구분해 표시한다.
E. Leak Trace Graph
• 기능: 최초 게시물, 동일 콘텐츠 URL, 유사 콘텐츠, 도메인을 노드로 연결하고 확인된 관계(실선)와 추정 관계(점선)를 구분한다.
• 주의: 같은 도메인이나 IP라는 사실만으로 동일 운영자라고 단정하지 않는다.
• 데모: 고정된 샘플 그래프다.
5.4 Evidence Vault (증거 보관함)
• 왜: 증거가 사라지거나 변조 의심을 받으면 신고와 삭제 모두 어려워진다.
• 기능: 파일 업로드 → SHA-256 생성 → 증거 ID, 수집 시각, 출처 기록 → 이력 조회
• 데모: 파일은 브라우저 안에서만 해시되고 외부로 전송되지 않는다.
• 주의: 해시는 무결성 확인용이며 법적 증거능력을 자동 보장하지 않는다.
5.5 Recover (EEG 기반 회복 지원)
• 왜: 삭제와 신고가 끝나도 심리적 회복은 별개의 과제다.
• 취지: 생체신호를 시각 피드백으로 바꿔 스스로 안정되는 경험을 돕는 보조 프로그램이다.
• 기능: 신호 시각화 → 대역별 파워(Delta, Theta, Alpha, Beta, Gamma) 계산 → 알파 비율에 따라 빛이 밝아지는 뉴로피드백 세션 → 세션 기록
• 데모: 가상 EEG 신호(SIMULATED)이며, 대역 파워는 실제 계산한다. 실제 장치 연동은 없다.
• 주의: 의학적 진단·치료를 대체하지 않고, EEG만으로 심리 상태를 단정하지 않는다.
5.6 Prevent (사전 예방)
• 왜: 같은 피해가 반복되지 않게 막는 것이 가장 좋은 보호다.
• 기능:
    ◦ 예방 체크리스트
    ◦ Trusted Circle(가족·지인 보호 그룹, 초대 링크 / 시뮬레이션)
    ◦ Invisible Watermark: 사진 업로드 시 「어디에, 어떤 목적으로」를 입력하면 일시가 자동으로 붙어 기록이 만들어지고, 이미지에는 기록 번호만 보이지 않게 들어간다. 검증하면 번호로 업로드 기록을 조회한다.
• 워터마크가 번호만 넣는 이유: 정보를 이미지에 직접 넣으면 추출하는 누구에게나 읽힌다. 번호만 넣고 내용은 본인 계정에 저장하면 본인만 조회할 수 있다.
• 한계: PNG 원본에서만 검출되고 JPEG 압축, 리사이즈, 캡처에는 사라질 수 있다. 유출자를 100% 특정한다는 의미가 아니다.
• 미구현: AI Face Privacy Filter(적대적 섭동). 테스트 모델과 효과 검증이 필요해 다음 단계로 미뤘다.
6. 데이터 구조 요약
Case(사례)를 중심으로 모든 데이터가 연결된다.
• Case 1 : N Report, MediaAsset, TraceResult, Evidence, RemovalRequest, MonitoringRecord, SecurityFinding
• TraceResult 1 : N RemovalRequest
• User 1 : N Case, EEGSession, PreventionRecord
• 모든 조작은 AuditLog에 기록한다(내용이 아니라 행동과 ID만).
• 서버 골격에서는 행 단위 접근 제한(RLS)으로 사용자별 데이터를 분리한다.
7. 하지 않는 것 (윤리·안전 선)
• 비공개 계정·채널 접근, 인증 우회, 무단 침입, 데이터 탈취, 악성코드
• 가해자 신상 직접 추적(수사기관 제출용 증거 정리까지만)
• 영구 삭제 보장, 법적 효력 보장, 의학적 진단
• 연결되지 않은 외부 API를 연결된 것처럼 표시하거나, 실제 검색 없이 실제 유출물을 발견했다고 표시

10. 파일 안내
• resafe.html: 화면이 있는 데모 전체. 더블클릭하면 브라우저에서 바로 실행된다(설치 불필요). 시연은 이 파일로 한다.
• resafe-next.zip: 실제 서비스용 서버 골격. npm install 후 Supabase 설정(README 참고)이 필요하고 화면은 아직 포함되어 있지 않다.
• 위 두 파일은 별개이며, 4단계에서 합칠 예정이다.
11. 시연 시나리오 (3분 버전)
1.  Report에서 AI와 대화해 피해를 접수하고 진술서를 받는다.
2.  Trace & Remove에서 후보를 확인하고 「피해 확인」으로 판정한다.
3.  증거로 등록하고 삭제 요청을 만든다.
4.  기준 이미지를 등록한 뒤 변형 이미지로 재유포 탐지를 보여 준다.
5.  Recover에서 뉴로피드백 세션을 실행한다.
6.  Prevent에서 워터마크를 삽입하고 검증해 업로드 기록이 조회되는 것을 보여 준다.
7.  Dashboard에서 전체 진행률과 보고서를 확인한다.
발표 핵심 메시지: 피해자가 한 번만 말하면 나머지는 AI가 돕고, 그 데이터가 피해자를 다시 해치지 않도록 설계했다.
